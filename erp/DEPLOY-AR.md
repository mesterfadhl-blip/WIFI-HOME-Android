# نشر النسخة الجديدة للهاتف والكمبيوتر

هذا الإعداد ينشر خادم Python وقاعدة SQLite واحدة على Render، مع HTTPS وقرص دائم. لم يتم إنشاء خدمة عامة تلقائياً: يلزم حساب Render يملكه المستخدم. خطة Starter والقرص الدائم مدفوعان؛ راجع السعر الظاهر في لوحة Render قبل إنشاء الموارد. لا تعتمد على خدمة مجانية بقرص مؤقت لحفظ بياناتك.

1. افتح https://dashboard.render.com/blueprints ثم اختر New Blueprint Instance، وسجّل الدخول بواسطة GitHub إذا لزم.
2. اختر المستودع `mesterfadhl-blip/WIFI-HOME-Android` والفرع `codex/erp-server-foundation`. ملف Blueprint هو `render.yaml` في الجذر.
3. أدخل `ERP_ADMIN_NAME` كاسم المدير و`ERP_ADMIN_PASSWORD` كلمة مرور جديدة قوية من 12 حرفاً على الأقل داخل لوحة Render فقط. لا ترسلها بالمحادثة.
4. راجع الخطة والقرص والتكلفة ثم اختر Deploy Blueprint. عندما تصبح الخدمة Live افتح عنوان HTTPS الذي تعرضه Render وسجّل الدخول بالبيانات التي اخترتها. يعمل العنوان نفسه من الهاتف والكمبيوتر.

ينشأ المدير قبل استقبال الاتصالات لمنع أي زائر من الاستيلاء على الإعداد الأول. إعادة التشغيل لا تغيّر كلمة مرور المستخدم الموجود، وتغيير متغير كلمة المرور ليس إعادة تعيين لكلمة مرور الحساب.

قاعدة البيانات تحت `/var/data/wifi-home/`. لا ترفع قاعدة تطوير أو بيانات تجريبية إلى GitHub. لا تحذف القرص ولا تغيّر المسار ولا تنشئ نسخاً مستقلة من الخدمة؛ لن تتشارك ملفات SQLite بين خوادم منفصلة. الخدمة مثيل واحد بأربع خيوط، وليست خادم التطوير المحلي. فحص `/healthz` لا يعرض بيانات محاسبية.

التحديث التلقائي معطّل: خذ نسخة احتياطية قبل النشر اليدوي لتحديثات تغيّر المخطط. توجد أداة نسخ متسق:

```sh
python -m erp.backup /var/data/wifi-home/data.sqlite3 /var/data/wifi-home/backup-YYYY-MM-DD.sqlite3
```

نسخة على نفس القرص لا تحمي من فقد القرص؛ يلزم حفظ النسخ خارجه. لم تتم تهيئة نسخ احتياطية تلقائية خارجية. لا تستخدم خيار pre-deploy للترحيل لأنه قد لا يملك قرص الخدمة؛ التهيئة والترحيلات تُنفذ عند بدء الخدمة.
