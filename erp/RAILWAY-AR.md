# النشر على Railway من الهاتف

هذا بديل Render. ملفات النشر جاهزة في GitHub؛ لم تُنشأ خدمة عامة، ولا يوجد حساب Railway متصل ببيئة التطوير. لا تحتاج تنزيل ملفات إلى الهاتف أو رفع ملف مضغوط.

## ربط المشروع

1. افتح https://railway.com/login واختر GitHub. قد تطلب المنصة تحققاً إضافياً؛ لا نضمن تجاوز مشكلة تسجيل لدى أي مزوّد.
2. اختر New Project ثم Deploy from GitHub repo، واسمح لـ Railway بالوصول إلى المستودع `mesterfadhl-blip/WIFI-HOME-Android` فقط إذا طلب ذلك.
3. افتح إعدادات الخدمة Settings ثم Source، واختر الفرع **`codex/erp-server-foundation`**. اترك Root Directory عند جذر المستودع، وConfig File عند `/railway.json`. لا تستخدم `main` لأنه يحتوي النسخة القديمة.

## التخزين والمتغيرات

4. أضف Volume للخدمة نفسها، عبر قائمة إنشاء الموارد أو قائمة الخدمة، وحدد Mount Path بالقيمة `/var/data`. القرص مورد منفصل ولا ينشئه ملف `railway.json` تلقائياً. لا تضف قاعدة PostgreSQL؛ التطبيق الحالي يستخدم SQLite.
5. من Variables أضف القيم التالية. يمكن استخدام Raw Editor للأربعة أسطر، مع استبدال كلمة المرور داخل Railway فقط:

```dotenv
ERP_DATABASE=/var/data/wifi-home/data.sqlite3
ERP_COOKIE_SECURE=1
ERP_ADMIN_NAME=admin
ERP_ADMIN_PASSWORD=REPLACE_WITH_A_PRIVATE_PASSWORD_AT_LEAST_12_CHARACTERS
```

كلمة المرور الموضحة مجرد موضع استبدال؛ لا تستخدمها كما هي. اختر كلمة قوية خاصة بك من 12 حرفاً على الأقل، ولا ترسلها بالمحادثة. تنشأ بيانات المدير قبل استقبال الطلبات العامة. متغير `PORT` تضبطه Railway تلقائياً؛ لا تحتاج تعيينه يدوياً.

6. راجع تسعير Railway والرصيد المطلوب، ثم طبّق التغييرات وانشر الخدمة. لا نفترض أن تشغيلها الدائم مجاني؛ التشغيل والقرص لهما تكلفة حسب حسابك وخطتك. لم يتم شراء أي موارد من هذه الجلسة.
7. عند نجاح النشر، افتح Settings ثم Networking ثم Generate Domain. إذا طلب منفذ الخدمة استخدم القيمة التي خصصتها Railway في `PORT`. افتح عنوان **HTTPS** وسجّل الدخول بالاسم وكلمة المرور اللذين اخترتهما. نفس الرابط والحساب يعملان على الهاتف والكمبيوتر.

قد تفشل المحاولة الأولى تلقائياً قبل إضافة القرص والمتغيرات؛ هذا مقصود لمنع استقبال زيارات دون مدير أو حفظ بيانات في قرص مؤقت. أعد النشر بعد إكمال الإعداد. راجع Deploy Logs عند فشل آخر، ولا تشارك كلمات المرور أو ملف قاعدة البيانات.

## استمرار البيانات والتحديث

حافظ على خدمة واحدة ومثيل واحد وVolume واحد. التطبيق يتحقق عند تشغيله على Railway من أن مسار قاعدة البيانات داخل القرص المرفق. إعادة التشغيل والنشر تستخدمان نفس البيانات؛ حذف القرص يفقدها. تغيير متغير كلمة مرور المدير بعد التهيئة لا يعيد تعيين كلمة مرور الحساب الموجود.

عطّل النشر التلقائي من GitHub قبل إدخال بيانات حقيقية، وخذ نسخة متسقة قبل التحديثات بواسطة `python -m erp.backup` وفق [دليل النظام](README.md). نسخة على نفس القرص وحده لا تحمي من فقده؛ النسخ الخارجية الآلية لم تُجهز بعد. لا تنقل قاعدة بيانات التطوير ولا بيانات الاختبارات إلى الاستضافة.

لا ترفع هذه الملفات إلى Netlify Drop؛ التطبيق الجديد يحتاج الخادم الذي تبنيه Railway من `erp/Dockerfile`.
