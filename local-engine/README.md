# نفس النظام داخل المتصفح — Python + SQLite محلياً

هذه الحزمة تشغّل **نفس** `erp/server.py` ووحدات الأعمال وقوالب المستندات وملفات `erp/static/` داخل Pyodide 0.27.7، ولا تستخدم `web/core.mjs` أو الواجهة المحلية البديلة. تعديل الواجهة مقتصر على وصف مكان التخزين وإضافة أزرار حفظ الحزمة وقاعدة البيانات؛ الأقسام والحسابات وعمليات الترحيل هي نفسها.

## محتويات الحزمة الخاصة

`WIFI-HOME-FULL.html` يشمل المحرك وملفات النظام ونسخة SQLite الابتدائية داخل الملف. `DATABASE.sqlite3` نسخة منفصلة من قاعدة البداية نفسها. لا توجد ملفات تشغيل مطلوب تنزيلها بعد ذلك، ولا يحتاج الهاتف Python أو خادماً أو استضافة.

لم تُضمّن أي بيانات شخصية في المستودع أو الحزمة العامة السابقة. بيانات صاحب النظام تأتي فقط من وسيطة `--database` وتُكتب في مجلد خاص خارج المستودع. **لا ترفع HTML الخاص أو قاعدة البيانات إلى GitHub.** الحزمة المحتوية بيانات العميل تحفظ محلياً للتسليم الخاص.

أول فتح ينشئ المدير إذا لم يكن موجوداً؛ حسابات الدخول وكلمات مرور التطبيق القديم لم تُستورد. عند إعادة الفتح من آخر حزمة محفوظة يستعمل النظام حساب المدير الموجود فيها. كلمات المرور تُشتق باستخدام نفس scrypt، والطلبات تستخدم نفس الجلسة وCSRF داخل المحرك، لكن حيازة ملف SQLite/HTML تتيح الوصول إلى البيانات؛ الملف ليس مشفراً ولا يمثل بديلاً لصلاحيات خادم متاح للآخرين.

## البيانات المحلية

كل طلب API يمر إلى تطبيق WSGI داخل ذاكرة المتصفح، دون شبكة. الطلبات مرتبة لمنع تنازع المعاملات. تُحفظ نسخة SQLite متسقة بعد نجاح التغييرات في localStorage عند إتاحته. إذا منعه موفر الملفات أو امتلأت المساحة يظهر تنبيه وتظل العمليات في الذاكرة، ويجب الضغط على **حفظ نسخة النظام ببياناتي** قبل الإغلاق.

زر الحفظ ينزل HTML جديداً يتضمن آخر قاعدة بيانات، بهوية تخزين جديدة تمنع استبداله بحالة قديمة من المتصفح. افتح أحدث ملف محفوظ في المرة القادمة. زر **تنزيل قاعدة البيانات** ينزل SQLite متسقة مستقلة. تأكد من وجود الملفات فعلياً في التنزيلات؛ لا يكفي ظهور رسالة طلب التنزيل.

لا توجد مزامنة بين الهواتف أو تشغيل خدمة نسخ S3 خلفية دون اتصال. كل ملف نسخة مستقلة. لا تحذف ملفات النسخ أو بيانات المتصفح قبل الاحتفاظ بنسخة خارجية.

## الأقسام والحدود

جميع وحدات الخادم المبنية حالياً موجودة: العملاء والأصناف، المبيعات ومسوداتها والتعديل والعكس، القبض والتخصيص وأعمار الديون، الموردون والمشتريات، أوامر الشراء والاستلام والفوترة المطابقة، مرتجعات العملاء والموردين، البنوك والمطابقة، المستودعات والتحويلات، المحاسبة والمركز المالي، الإقفال وإعادة الفتح، المستخدمون وسجل التدقيق والمخرجات المستقلة.

هذا يحافظ على كل ما بُني من النظام الجديد؛ لا يعني إكمال كل وظائف ERP التجارية التي لا تزال خارج الإصدار وفق `erp/OPERATIONS-AR.md`، مثل تخصيص صلاحيات فردية وتجميع الاستلامات وفروقات أسعار الفوترة. طباعة PDF تعتمد على دعم المتصفح؛ يمكن حفظ المستند كملف HTML مستقل عند عدم دعمها.

حجم HTML نحو 22 ميغابايت، ويحتاج متصفحاً حديثاً يدعم WebAssembly وJavaScript وذاكرة كافية. الاختبار جرى في Chromium بحجم شاشة الهاتف؛ لم يُختبر على هاتف أندرويد فعلي. سياسة بيئة الاختبار تمنع تنقل `file://`، لذلك جرى تحميل ملف الاختبار من خادم محلي ثم تعطيل الشبكة تماماً. الملف الموزع نفسه يحتوي كل الموارد، ولا يطلب اتصالاً خارجياً؛ موفر ملفات الهاتف هو الذي يحدد السماح بتنفيذ HTML وWASM.

## إعادة البناء والتحقق

أدوات البناء فقط: Python وNode، ونسخة حزمة npm الرسمية `pyodide@0.27.7` مفكوكة خارج المستودع، وثلاث حزم stdlib (`sqlite3`, `hashlib`, `openssl`) من توزيعة Pyodide الرسمية. يفحص البناء SHA-256 للحزم مقابل `pyodide-lock.json`؛ لا يعطل TLS. تضمّن الحزمة الموزعة تراخيص المكونات.

```sh
python scripts/build_full_local.py /private/output/WIFI-HOME-FULL.html \
  --runtime /path/to/pyodide/package \
  --database /private/data.sqlite3
```

بإسقاط `--database` تنشأ حزمة عامة فارغة. **لا تبن نسخة خاصة داخل مجلد متعقب في Git.**

تم تمرير 65 اختباراً للخادم نفسه داخل Pyodide، بما فيها SQLite وscrypt والمعاملات والمخزون والمراجعات والإقفالات. `scripts/check_full_local_browser.py` يفحص واجهة الهاتف والبيانات الأساسية والشراء والاستلام والفوترة والقبض والتخصيص والبنوك والمرتجعات والمركز المالي والمستند ونسخ SQLite/HTML والاستعادة، مع تعطيل التخزين والشبكة. يستخدم ملفاً خاصاً مجهزاً محلياً ولا يقرأ بيانات من مستودع عام.
